## 가드레일이 잡은 문제

- 벤치마크 전용 태그를 운영 코드가 참조하는 우회(리드 검토). 이후 `diff-policy`에 `BENCHMARK_ONLY_MARKERS` 규칙을 추가함
- 검사 통과율 504/504가 문항 품질 개선을 뜻하지 않은 사례(면접위원장 관점 검토). 사례 두 개를 요구하는 문장, 기술을 절차 준수로 바꾼 문장 등
- 교차 검토가 찾은 정확 일치 위반 3건(R1-A 1건, 통합 2건)과 시간 예산 문제 2건
- 부하 중 지연시간 오탐: 교차 측정(같은 시점, 번갈아 실행)으로 확인한 뒤 예외 기록
- Windows `time.sleep` 오차로 불안정한 테스트 1건(단언 기준을 실제 측정 시각으로 바꿈)

## 남은 과제

- 매트릭스 통과율 1.0을 "자연스러운 문장 100%"로 보지 않음. 면접위원장 관점 검토에서 검사가 못 잡는 결함이 라운드마다 나왔음
- KSA 표면 중 기술 16개 규칙(수집·설정 등)은 그대로이고, 태도 표면은 "원활한 커뮤니케이션을 실행하는 적극적인 행동"처럼 원문 명사화가 남음
- "보고서를 직접 작성한"처럼 대상과 동사를 나눈 문장은 측정 검사 `ksa_type_operationalized`가 표면 원형을 요구해 쓰지 못함. 검사를 고치는 별도 과제가 필요함(검사 변경이라 리드 검토 대상)
- NCS MCP `ncs_search`가 로컬에서 호출당 0.9~1.4초. 저장 JD 벤치마크 시간의 대부분이며 NCS_MCP 저장소 쪽 작업이 필요함
- 이미지 PDF OCR이 건당 7~25초이고 부하 중 120초 제한을 넘는 경우가 있음(304117)
- 번호 복구의 부분 문자열·6자 이내 예외는 기준선부터 있던 규칙이고 오늘은 범위만 좁힘
- 모델이 만든 후속 질문이 게이트를 통과하면 경험면접 역할·문제 슬롯이 강제되지 않음

## 팀 운영 기록

- Cursor Agent CLI를 Git Bash에서 실행하면 Orca가 설치한 Cursor 훅(PowerShell 명령)이 구문 오류로 도구 호출을 모두 막음. PowerShell에서 `node.exe index.js`로 실행하면 정상
- Cursor 기본 모델(gpt-5.6-sol)은 08:11에 월 사용 한도에 도달함. 지출 한도는 설정하지 않았고, 이후에는 Auto 모델로 읽기 전용 교차 검토만 맡김
- Codex `workspace-write` 샌드박스는 anaconda 패키지 읽기가 막혀 pytest가 돌지 않음. 구현은 사용자 설정(`danger-full-access`)으로 하고, 안전장치는 worktree 분리, `diff-policy`, 리드 판정으로 대신함. 통합 검토는 `-s read-only`로 실행함
- 지연시간 KPI는 구현자가 동시에 측정을 돌리면 25% 넘게 흔들림. 라운드 중에는 교차 측정으로 확인하고, 최종 판정은 단독 측정으로 함
